Signet Test Harness

Dev-only test consumer for Sign-in-with-Signet flows.

Change to http://localhost:5174 (or https://localhost:5174 if your dev server has mkcert certs) to test a local build instead of the live site.
Every result is checked cryptographically on the callback page and appended to test-consumer/results/log.jsonl, so a failed sign-in can be read back later instead of described from memory.
Testing on a phone? The sign-in contract only accepts an https:// or localhost consumer, so a plain http:// LAN address is rejected before Signet even asks. Serve this harness over https (see the README) and open its LAN URL on the phone, accepting the certificate warning once.

Cross-device (relay mode)

Cross-device sign-in
The relay path used by the Android consumer apps: Signet gift-wraps its answer to a session key and publishes it to a relay instead of redirecting. Runs on its own page, because the listener has to stay open while you approve.
